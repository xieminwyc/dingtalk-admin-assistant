# 知识卡片与事务目录整理模板

> 当前项目的内容输入方式是：  
> `钉钉文档 -> 人工整理成 Markdown 卡片 -> 本地卡片/事务目录 -> 钉钉机器人回复`

这份模板的目标不是做一个完整 CMS，而是让业务同学先用最轻量的方式把高频内容交给研发接入。

---

## 使用原则

- 一条卡片只表达一个稳定主题
- 知识卡片回答“规则是什么、怎么理解”
- 事务目录回答“我要办什么、入口在哪里”
- 标题尽量贴近员工自然问法
- 关键词尽量写员工真的会说的话

---

## 1. 知识卡片模板

适合这类问题：

- `年假规则是什么`
- `补卡制度怎么规定`
- `权限申请说明`

模板：

```md
---
type: knowledge
id: card-xxx
title: 标题
department: HR | 行政 | IT
keywords:
  - 关键词1
  - 关键词2
scope: 适用范围，可选
---

这里写标准答案正文。

要求：
1. 尽量写成可以直接发给员工看的完整句子
2. 不要把多条制度混在一张卡里
3. 如果答案依赖最新公告，正文里要写“以最新制度公告为准”
```

示例：

```md
---
type: knowledge
id: card-hr-annual-leave
title: 年假规则
department: HR
keywords:
  - 年假
  - 休假
  - 司龄
scope: 适用于正式员工年假政策查询
---

年假天数按司龄计算，试用期不单独享有年假，具体以 HR 制度公告为准。
```

---

## 2. 事务目录模板

适合这类问题：

- `我要请假`
- `帮我报销`
- `我要开权限`

模板：

```md
---
type: task
taskType: 事务稳定 code
title: 标题
keywords:
  - 关键词1
  - 关键词2
entryUrl: 入口链接，可为空
fallbackContact: 找不到入口时联系谁
---

description:
这里写事务说明，告诉员工这是干什么的。

preparations:
- 办理前准备1
- 办理前准备2
- 办理前准备3
```

示例：

```md
---
type: task
taskType: leave_application
title: 请假申请
keywords:
  - 请假
  - 休假
  - 年假
  - 病假
entryUrl: https://oa.example.com/tasks/leave-application
fallbackContact: HR 同学
---

description:
用于发起请假审批，适合年假、病假、事假等场景。

preparations:
- 确认请假日期
- 准备请假类型
- 提前和直属主管沟通
```

---

## 3. 整理建议

- 每个部门先给 5 到 10 条最高频知识卡片
- 每个部门先给 2 到 5 个最高频事务入口
- 优先整理“员工最常问、最常办、最容易转人工”的内容

建议第一批优先覆盖：

- HR：年假、请假、补卡、入离职
- 行政：会议室、办公用品、访客、证明
- IT：权限开通、账号、设备报修

---

## 4. 交付给研发时需要什么

你给研发的材料，最少包含：

- 原始钉钉文档链接
- 按上面模板整理后的 Markdown
- 如果有入口，给出真实链接
- 如果没有入口，给出明确兜底联系人

这样研发侧就可以把内容落到：

- 知识卡片
- 事务目录
- 后续外部 RAG Provider 的接入配置

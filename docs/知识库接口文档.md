## 基础信息

- **Base URL**: `http://192.168.30.68:13718\`
- **Content-Type**: `application/json; charset=utf-8`
- **鉴权**: 若服务配置了 `API_KEYS`，所有业务接口需携带 `Authorization: Bearer <key>`

---

## 通用错误响应

```json
{
  "error": "错误描述信息"
}
```

常用 HTTP 状态码：

- `200` - 成功
- `202` - 任务已接受（异步处理）
- `400` - 请求参数错误
- `401` - API Key 无效或缺失
- `404` - 资源不存在
- `409` - 状态冲突
- `500` - 服务器内部错误
- `503` - 服务未就绪

## 1. 健康检查接口

### 1.1 基本健康检查

**GET** `/healthz`

检查服务基本存活状态。无需鉴权。

```bash
curl http://192.168.30.68:13718/healthz

```

**响应**：

```json
{ "status": "ok" }
```

---

### 1.2 就绪检查

**GET** `/readyz`

检查服务所有依赖（数据库、索引）是否就绪。无需鉴权。

```bash
curl http://192.168.30.68:13718/readyz

```

**响应**（成功）：

```json
{
  "status": "ok",
  "checks": [
    { "name": "db", "status": "ok" },
    { "name": "index", "status": "ok" }
  ]
}
```

**响应**（失败，HTTP 503）：

```json
{
  "status": "fail",
  "checks": [
    { "name": "db", "status": "ok" },
    { "name": "index", "status": "fail", "error": "connection timeout" }
  ]
}
```

> `checks` 数组中的条目取决于服务启动时注入的组件：注入了数据库则检查 `db`，注入了索引（OpenSearch）则检查 `index`，未注入的组件不出现在 checks 中。

## 2. 知识库查询接口

### 2.1 搜索知识库

**POST** `/api/v1/knowledge/search`

跨文档搜索相关的 chunk 段，结果经钉钉实时 ACL 过滤。

**字段说明**：

| 字段               | 类型   | 必填 | 说明                                                                 |
| ------------------ | ------ | ---- | -------------------------------------------------------------------- |
| `query`            | string | 是   | 搜索查询文本                                                         |
| `operatorId`       | string | 是   | 操作者 unionId（用于 ACL 过滤和审计）                                |
| `workspaceId`      | string | 否   | 限定 workspace，不填则跨所有 workspace                               |
| `maxResults`       | int    | 否   | 返回数量，默认 10，上限 50                                           |
| `directoryId`      | string | 否   | 限定目录范围                                                         |
| `nextToken`        | string | 否   | 分页游标（来自上一次响应）                                           |
| `searchMode`       | string | 否   | `fulltext`（默认）或 `keyword`                                       |
| `excludeImageData` | bool   | 否   | 设为 `true` 时结果中不返回 base64 图片数据；默认 `false`（返回图片） |

```bash
curl -X POST http://192.168.30.68:13718/api/v1/knowledge/search \
  -H "Authorization: Bearer a9b5fcaf-f5e3-43a6-bb31-6dd4611560ac" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "如何申请年假",
    "operatorId": "abc123xyz",
    "maxResults": 10
  }'

```

跨 workspace 指定目录搜索：

```bash
curl -X POST http://192.168.30.68:13718/api/v1/knowledge/search \
  -H "Authorization: Bearer a9b5fcaf-f5e3-43a6-bb31-6dd4611560ac" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "绩效考核流程",
    "operatorId": "abc123xyz",
    "workspaceId": "ws_001",
    "directoryId": "dir_hr",
    "maxResults": 5,
    "searchMode": "keyword"
  }'

```

**响应**：

```json
{
  "items": [
    {
      "chunkId": 123,
      "documentId": 456,
      "title": "员工手册 2025",
      "chunkText": "年假申请需提前 3 个工作日...",
      "headingPath": "第三章 > 假期制度",
      "pageNo": 12,
      "score": 0.95,
      "sourceUrl": "https://alidocs.dingtalk.com/...",
      "imageData": "iVBORw0KGgoAAAANS..."
    }
  ],
  "nextToken": "eyJvZmZzZXQiOjEwfQ==",
  "total": 42
}
```

### 2.2 获取上下文窗口

**POST** `/api/v1/knowledge/context`

**字段说明**：

| 字段                     | 类型        | 必填   | 说明                        |
| ------------------------ | ----------- | ------ | --------------------------- |
| `chunkId`                | int64       | 二选一 | chunk ID                    |
| `documentId` + `chunkNo` | int64 + int | 二选一 | 文档 ID + chunk 序号        |
| `windowSize`             | int         | 否     | 前后各取 N 个 chunk，默认 2 |

方式一：通过 chunkId：

```bash

  -H "Content-Type: application/json" \

    "chunkId": 123,
    "windowSize": 3
  }'

```

### 2.4 知识库问答（同步）

**POST** `/api/v1/knowledge/ask`

基于知识库 RAG 问答，**支持多轮对话**。流程：加载历史 → 将追问改写为独立问题 → 检索相关片段 → 携带历史调用 LLM → 保存本轮 → 返回答案。

ACL 过滤沿用 `/search` 的逻辑，只使用当前 `operatorId` 可访问的内容作答。

**会话管理**：

- 首次提问不传 `sessionId`，服务端自动创建新会话并在响应中返回 `sessionId`
- 后续请求带回该 `sessionId` 即可继续对话
- 会话历史保存在服务端内存，**2 小时**无活动后自动清除
- 每个会话最多保留最近 **10 轮**历史（防止 token 过长）
- 调用 `DELETE /api/v1/knowledge/sessions/{sessionId}` 可主动清除

**请求字段**：

| 字段               | 类型   | 必填 | 说明                                              |
| ------------------ | ------ | ---- | ------------------------------------------------- |
| `question`         | string | 是   | 用户问题                                          |
| `operatorId`       | string | 是   | 操作者 unionId（用于 ACL 过滤和审计）             |
| `sessionId`        | string | 否   | 会话 ID；不传则由服务端创建新会话                 |
| `workspaceId`      | string | 否   | 限定 workspace，不填则跨所有 workspace            |
| `maxSources`       | int    | 否   | 参与回答的检索片段数，默认 5                      |
| `excludeImageData` | bool   | 否   | 设为 `true` 时 `sources` 中不返回 base64 图片数据 |

首次提问（创建新会话）：

```bash
curl -X POST http://192.168.30.68:13718/api/v1/knowledge/ask \
  -H "Authorization: Bearer a9b5fcaf-f5e3-43a6-bb31-6dd4611560ac" \
  -H "Content-Type: application/json" \
  -d '{
    "question": "报销流程是什么？",
    "operatorId": "abc123xyz",
    "maxSources": 5,
    "excludeImageData": true
  }'

```

继续同一会话（多轮追问）：

```bash
curl -X POST http://192.168.30.68:13718/api/v1/knowledge/ask \
  -H "Authorization: Bearer a9b5fcaf-f5e3-43a6-bb31-6dd4611560ac" \
  -H "Content-Type: application/json" \
  -d '{
    "question": "那餐饮费怎么报？",
    "operatorId": "abc123xyz",
    "sessionId": "f5a8c7d1f2b34c6e9a0b1c2d3e4f5678"
  }'

```

**响应**（`Content-Type: application/json`）：

```json
{
  "sessionId": "f5a8c7d1f2b34c6e9a0b1c2d3e4f5678",
  "answer": "根据《员工手册 2025》，餐饮费报销需提交业务招待费申请...",
  "source": ["https://alidocs.dingtalk.com/i/nodes/xxx"],
  "pics": [
    {
      "name": "图1",
      "data": "iVBORw0KGgoAAAANS...",
      "preview": "报销流程示意图..."
    }
  ]
}
```

**响应字段说明**：

| 字段        | 类型   | 说明                                                        |
| ----------- | ------ | ----------------------------------------------------------- |
| `sessionId` | string | 会话 ID，后续多轮对话时带回                                 |
| `answer`    | string | LLM 生成的回答，可能含 `{{图N}}` 占位符引用 `pics` 中的图片 |

| `source` | \[ \]string | 本次参与回答的文档来源 URL 列表（按文档去重，非 chunk 级别） |

| `pics` | \[ \]object | 答案中引用到的图片列表；`excludeImageData: true` 时为空数组 |

| `pics[ ].name` | string | 图片名称，如 `图1`，对应答案中的 `{{图1}}` 占位符 |

| `pics[ ].data` | string | base64 编码的图片字节 |

| `pics[ ].preview` | string | 图片所在 chunk 的文字描述（前 100 个字符） |

常见错误：

| 状态码 | 原因                                           |
| ------ | ---------------------------------------------- |
| `400`  | 缺少 `question` 或 `operatorId`                |
| `503`  | LLM 客户端未配置（`ANTHROPIC_API_KEY` 未设置） |

### 2.5 知识库问答（流式 SSE）

**POST** `/api/v1/knowledge/ask/stream`

功能与 `2.4` 完全相同，区别在于响应采用 **Server-Sent Events（SSE）**，LLM 生成的内容逐块实时推送，适合需要打字机效果的前端场景。

会话管理逻辑与 `2.4` 一致（`sessionId` 可选、2 小时 TTL）。

**请求字段**：与 `POST /api/v1/knowledge/ask` 完全相同。

```bash
curl -X POST http://192.168.30.68:13718/api/v1/knowledge/ask/stream \
  -H "Authorization: Bearer a9b5fcaf-f5e3-43a6-bb31-6dd4611560ac" \
  -H "Content-Type: application/json" \
  -d '{
    "question": "出差住宿标准是多少？",
    "operatorId": "abc123xyz",
    "sessionId": "f5a8c7d1f2b34c6e9a0b1c2d3e4f5678",
    "excludeImageData": true
  }'

```

**响应**（`Content-Type: text/event-stream`）：

增量内容逐块推送（每次携带新生成的文字片段）：

```plaintext
data: {"type":"chunk","content":"根据"}

data: {"type":"chunk","content":"《员工"}

data: {"type":"chunk","content":"手册 2025》，住宿标准如下..."}

```

结束事件（携带会话 ID 和本次检索的来源 chunk 列表）：

```plaintext
data: {"type":"done","sessionId":"f5a8c7d1f2b34c6e9a0b1c2d3e4f5678","sources":[{"chunkId":123,"documentId":456,"title":"员工手册 2025","chunkText":"...","score":0.87,"sourceUrl":"https://..."}]}

data: [DONE]

```

> **注意**：流式接口的 `done.sources` 是完整的 chunk 对象数组（与 `/search` 结果结构相同），与同步接口 `2.4` 的 `source`（去重 URL 字符串列表）不同。

错误事件：

```plaintext
data: {"type":"error","message":"错误描述信息"}

```

> **客户端使用建议**：每收到一个 `chunk` 事件，将 `content` 追加到已显示文本末尾；收到 `done` 事件时渲染引用来源列表；收到 `[DONE]` 或连接断开时关闭流。

### 2.6 清除会话

**DELETE** `/api/v1/knowledge/sessions/{sessionId}`

主动清除指定会话的历史记录。用户退出对话或需要重置上下文时调用。

```bash
curl -X DELETE http://192.168.30.68:13718/api/v1/knowledge/sessions/f5a8c7d1f2b34c6e9a0b1c2d3e4f5678 \
  -H "Authorization: Bearer a9b5fcaf-f5e3-43a6-bb31-6dd4611560ac"

```

**响应**：HTTP `204 No Content`（无响应体）

> **说明**：会话不存在或已过期时同样返回 204，操作幂等。清除后，若使用相同 `sessionId` 继续提问，服务端会以空历史重新开始对话（等效于新建会话）。

## 3. 知识库摄取接口

### 3.1 扫描入库（异步）

**POST** `/api/v1/knowledge/scan`

接受钉钉文档或文件夹 URL，创建异步扫描任务并立即返回。Worker 自动完成扫描 → 入库 → 拉取 → 分块 → 向量化 → 写索引的完整流程。

**字段说明**：

| 字段  | 类型   | 必填 | 说明                                                       |
| ----- | ------ | ---- | ---------------------------------------------------------- |
| `url` | string | 是   | 钉钉文档或文件夹链接（必须为 `alidocs.dingtalk.com` 域名） |

扫描单个文档：

```bash
curl -X POST http://192.168.30.68:13718/api/v1/knowledge/scan \
  -H "Authorization: Bearer a9b5fcaf-f5e3-43a6-bb31-6dd4611560ac" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://alidocs.dingtalk.com/i/nodes/xxx"
  }'

```

扫描整个文件夹：

```bash
curl -X POST http://192.168.30.68:13718/api/v1/knowledge/scan \
  -H "Authorization: Bearer a9b5fcaf-f5e3-43a6-bb31-6dd4611560ac" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://alidocs.dingtalk.com/i/nodes/folder\_xxx"
  }'

```

**响应**（HTTP 202 Accepted）：

```json
{
  "taskId": 88,
  "status": "pending"
}
```

### 4.2 重试失败任务

**POST** `/api/v1/tasks/{id}/retry`

将状态为 `failed` 或 `dead` 的任务重置为 `pending`，触发重试。

```bash
curl -X POST http://192.168.30.68:13718/api/v1/tasks/88/retry \
  -H "Authorization: Bearer a9b5fcaf-f5e3-43a6-bb31-6dd4611560ac"

```

**响应**：

```json
{
  "taskId": 88,
  "status": "pending"
}
```

任务状态不为 `failed`/`dead` 时返回 HTTP 409：

```json
{ "error": "task is not in a retryable state" }
```

配置 `API_KEYS` 环境变量后，所有非健康检查接口都需要在请求头携带：

```plaintext
Authorization: Bearer <key>

```

**测试用 API Key**：

```plaintext
a9b5fcaf-f5e3-43a6-bb31-6dd4611560ac
```
